# Phase 7 — 会议记录结构化摘录

[触发词: "处理会议纪要", "提取会议记录", "全自动处理未蒸馏纪要"]

## 任务目标

提取原始会议及调研记录中的量化参数与客观事实。过滤和清除主观情绪表达或无确切数据的陈述，统一生成含有 YAML 标签结构的情报卡片供归档。

## 数据操作域

- **提取路径**: 检索读取 `_Inbox/` 下所有的 `.md` 原始输入文本。
- **用户指令域**: 当用户手动圈点文档进行处理调用本指令时可直接处理该文件群。

## 处理步骤规范

### 步骤一：日期基准提取

提取长文核心内记载的会议产生/调研发生日期（严禁调用文件创建日期代替）。提取完成后设定其为该卡片的主日期 `[发生日期]` 并在后续文件定名处调用。

### 步骤二：归属子行业路径判定

根据原文的行业实体，匹配查找 `知识库/行业/` 下已创建的独立子行业文件夹名。

- 若可形成明确指向，确立对应的主目录名。
- 若原文系无明确专一行业主题的大框架宏观陈述，或跨物种复合品类（如“猪肉和菜油对 CPI 的影响”），不再卡流程询问，全数放入公有的独立存放库：`知识库/行业/` 内，后续交由打通的 YAML 标签系统实现精准关联检索。

### 步骤三：情报卡蒸馏与直接落盘

**蒸馏要求：情报卡只包含以下三节，严禁将原文正文复制进卡片。** 每节均须是从原文中提炼的精华，而非原文摘抄。严禁输出原文、摘录或任何超出三节结构的冗余内容。

将原文提炼为以下格式，**直接写入文件，无需展示预览，无需等待用户确认**：

```markdown
---
date: [会议或研报产生的标准日期 YYYY-MM-DD]
tags:
  - [如果是针对具体公司，请补充「公司」标签，否则补充「行业」标签]
  - [仅限行业/标的名称，≤5个，严禁描述性词汇]
  - [券商研报 / 专家访谈] （根据原文性质选填一个，标记为主观内容）
status: 活跃
importance: 一般
---
# 结构化提炼：[标的] (YYYY-MM-DD)

## 🧊 量化事实：因果逻辑链
[起因A] → [传导B] → [后果C]，附量化数据锚点（成本边界/开工率/库存天数等）
剔除所有无数字支撑的口号式表述。

## 🟡 立场定性
从下列选一：[明显看多推介] / [明显风险警示] / [具备对冲思考] / [无立场数据罗列]
一句话说明判断依据。

## 🎯 后续侦察定距点
[核算事项] | [最晚证实时间] | [若成真的行业影响]
```

### 步骤四：落盘 + 归档 + git 提交

直接执行，无需用户触发：

1. 将情报卡写入 `知识库/行业/[发生日期]_情报卡_[品种名]_[主题].md`（平铺，靠 YAML 标签分类）
2. 将原文从 `_Inbox/[原始文件名]` 移至 `_Inbox/_Processed_Archive/[原始文件名]`
3. 执行 git 提交：`git add [情报卡路径] && git commit -m “入库: [文件名]”`
4. 输出一行确认：`✅ 已入库: [完整路径] | 已 git 提交`
