# Agent Hub 架构总览

> 版本：2026-04-13 | 适用项目：`/home/zy/investment_system`

---

## 一、设计哲学

Agent Hub 的核心原则是**职责分层、接口隔离、即插即用**。

| 原则 | 体现 |
|------|------|
| 零耦合 Bot | 每个 Bot 是独立进程，互不影响 |
| 单一职责 | Channel 只收发消息，Skill 只写业务，Hook 只做横切 |
| 约定优于配置 | 放一个文件进对应目录，自动被发现注册 |
| 数据流单向 | `Channel → Context → Router → Skill → Channel`，Context 是唯一数据载体 |

## 二、五层架构

```
┌──────────────────────────────────────────────────────┐
│  Channel 层 (channels/)                               │
│  输入输出适配：飞书WS / CLI / 未来: HTTP / Telegram   │
├──────────────────────────────────────────────────────┤
│  Core 层 (core/)                                      │
│  BotLoader → BotRuntime → Router → Middleware         │
│  Executor → Registry → PendingStore                   │
├──────────────────────────────────────────────────────┤
│  Bot 层 (bots/<name>/)                               │
│  Skills + Hooks + Prompts + Memory (完全隔离)         │
├──────────────────────────────────────────────────────┤
│  Tools 层 (tools/)                                    │
│  全局共享工具：文件IO / 飞书API / 搜索 (无状态)       │
├──────────────────────────────────────────────────────┤
│  Providers 层 (providers/)                            │
│  AI 引擎适配：Claude CLI / DeepSeek API / 可扩展      │
└──────────────────────────────────────────────────────┘
```

## 三、消息完整流转路径

```
飞书用户发消息
    │
    ▼
Channel.on_message()
    │  创建 Context（request_id, user_id, raw_text）
    ▼
execute_in_runtime(runtime, ctx)          ← core/executor.py
    │
    ├─① Router.route(ctx)                 ← 四层匹配
    │      pending-confirm → URL检测 → Skill触发词 → Phase触发词 → AI分类 → kb_query兜底
    │      详见 CLAUDE.md「消息路由速查」章节
    │
    ├─② skill_registry.get_handler()      ← 查找处理函数
    │
    ├─③ ctx.metadata 注入运行时依赖
    │      _runtime / _pending_store / _dialog_history
    │
    ├─④ _resolve_provider_name()          ← Skill>Phase>Bot>全局 优先级
    │
    └─⑤ pipeline.execute(ctx, handler)    ← 洋葱模型
           [before hooks] dedup→auth→timer
           Skill.handle(ctx)
           [after hooks]  timer_after→audit
    │
    ▼
Channel.send_reply(ctx)
    │  ctx.reply_text → 飞书消息
    ▼
用户收到回复
```

## 四、进程架构（运行时）

```
bash start.sh --daemon
    │
    ├── main.py (investment Bot 主进程)
    │       └── investment_ds Bot (子进程 run_single_bot.py)
    │
    └── bots/daily_report/scheduler_runner.py (独立调度器)
```

- **main.py**：加载 `bots/investment/`，在当前进程运行飞书 WS Channel
- **子进程**：`bots/investment_ds/` 独立运行，避免 asyncio event loop 冲突
- **scheduler_runner.py**：APScheduler 定时驱动，不受 Agent Hub BotLoader 管理

## 五、目录结构

```
investment_system/
├── core/           # 框架核心（不要轻易修改）
│   ├── bot_loader.py      # Bot 发现与加载
│   ├── bot_runtime.py     # 单 Bot 隔离容器
│   ├── context.py         # 统一数据结构
│   ├── executor.py        # 执行引擎
│   ├── middleware.py      # Hook 管道（洋葱模型）
│   ├── registry.py        # 自动发现注册表
│   ├── router.py          # 四层路由（pending-confirm/URL/触发词/AI分类）
│   └── pending_store.py   # 待确认状态管理
├── channels/       # 渠道适配器（即插即用）
├── providers/      # AI 引擎适配器（即插即用）
├── hooks/          # 全局横切逻辑（即插即用）
├── tools/          # 无状态共享工具
├── bots/           # 各 Bot 业务代码（完全隔离）
│   ├── _template/         # 新 Bot 模板
│   ├── investment/        # Claude 投研 Bot
│   ├── investment_ds/     # DeepSeek 投研 Bot
│   ├── daily_report/      # 每日报告 Bot（独立调度）
│   └── health/            # 健康 Bot（占位）
├── daily_reporter/ # 旧版数据抓取层（daily_report Bot 复用）
├── docs/           # ← 你正在看的文档
├── main.py         # 系统入口
├── run_single_bot.py
└── start.sh        # 统一启动管理
```

> ⚠️ **Skills 同步规则**：`bots/investment/skills/` 和 `bots/investment_ds/skills/` 是内容相同的
> Copy（非 symlink）。修改任一 Bot 的 Skill 文件，**必须同步修改另一个**。
> 详见 `docs/08_文档设计反思_知识卡.md`。

## 六、架构已知问题与决策记录

### ✅ 已解决

| 问题 | 解决方案 |
|------|---------|
| 多 Bot asyncio 冲突 | 非主 Bot 走独立子进程 |
| DS Provider 缺少 system prompt | deepseek_api.py 已新增 `_DEFAULT_SYSTEM` |
| daily_reporter 游离在架构外 | 新建 `bots/daily_report/scheduler_runner.py` 接管 |
| tushare 午盘无实时数据 | 改用 akshare 东方财富 + yfinance 实时接口 |
| `ingest_file` ok 确认无法路由（DeepSeek 产生幻觉） | Router 新增第0层 pending-confirm 路由；`ingest_file` 改为单步直接入库 |

### ⚠️ 已知设计局限（有意为之）

| 局限 | 原因 | 应对 |
|------|------|------|
| `dedup._processed_ids` 是进程内内存 | 多进程 Bot 各有独立去重集合 | 各 Bot 独立飞书应用，message_id 天然不共享，无问题 |
| `daily_report` Bot 不走 BotLoader | APScheduler 驱动模型与 feishu_ws 不兼容 | scheduler_runner.py 自治，用 `enabled: false` 跳过 BotLoader |
| `ingest_record` 的 pending_store 用 user_id 做 key | 同一用户同时只能有一个待确认操作 | 符合使用场景，单人单线程交互 |
