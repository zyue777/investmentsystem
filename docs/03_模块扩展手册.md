## 一、新增 Channel（渠道适配器）

Channel 是消息的**入口和出口**，负责把外部消息转换为 Context，并把 Context 的 reply_text 发回去。

### 1.1 接口约定

```python
# channels/my_channel.py
from channels.base import ChannelBase
from core.context import Context, ChannelManifest

# 必须：MANIFEST（注意：channel 类型用 create_channel 工厂函数）
MANIFEST = ChannelManifest(name="my_channel", description="渠道描述")

class MyChannel(ChannelBase):
    def start(self, runtime):
        """
        启动监听，可以阻塞。
        runtime 包含：config / skill_registry / pipeline / router / pending_store
        """
        # 在监听循环中调用 self._handle(ctx)
        pass

    def send_reply(self, ctx: Context):
        """把 ctx.reply_text 发回给用户。"""
        pass

    def _handle(self, ctx: Context):
        """通用内部处理（继承自 ChannelBase）：执行 → 发回复"""
        from core.executor import execute_in_runtime
        ctx = execute_in_runtime(self._runtime, ctx)
        if ctx.reply_text:
            self.send_reply(ctx)

def create_channel():
    return MyChannel()
```

### 1.2 在 Bot 中使用

```yaml
# bot.yaml
channel: my_channel
channel_config:
  param1: value1
```

### 1.3 HTTP API Channel 示例

```python
# channels/http_api.py
from flask import Flask, request as req, jsonify
import threading

MANIFEST = ChannelManifest(name="http_api", description="HTTP REST 接口")

class HTTPAPIChannel(ChannelBase):
    def start(self, runtime):
        self._runtime = runtime
        app = Flask(__name__)

        @app.route('/message', methods=['POST'])
        def receive():
            data = req.json
            ctx = self.build_context(runtime,
                request_id=data.get('id', ''),
                user_id=data.get('user', 'api'),
                raw_text=data.get('text', ''),
            )
            ctx = execute_in_runtime(runtime, ctx)
            return jsonify({'reply': ctx.reply_text})

        app.run(host='0.0.0.0', port=8080)

    def send_reply(self, ctx): pass  # HTTP 是同步请求响应，不需要主动推送

def create_channel():
    return HTTPAPIChannel()
```

## 二、新增 Provider（AI 引擎适配器）

Provider 是 AI 能力的**统一接口**。换 Provider 不需要改任何 Skill 代码。

### 2.1 接口约定

```python
# providers/openai_api.py
import os
from openai import OpenAI
from providers.base import ProviderBase
from core.context import ProviderManifest

MANIFEST = ProviderManifest(name="openai_api", description="OpenAI Chat API")

class OpenAIProvider(ProviderBase):
    def call(self, prompt: str, timeout: int = 300, cwd: str = "", **kwargs) -> str:
        api_key = os.environ.get('OPENAI_API_KEY', '')
        if not api_key:
            return "❌ 未设置 OPENAI_API_KEY"
        client = OpenAI(api_key=api_key)
        try:
            resp = client.chat.completions.create(
                model=kwargs.get('model', 'gpt-4o'),
                messages=[
                    {"role": "system", "content": kwargs.get('system', '')},
                    {"role": "user", "content": prompt},
                ],
                timeout=timeout,
            )
            return resp.choices[0].message.content.strip()
        except Exception as e:
            return f"❌ OpenAI 失败: {e}"

    def check_available(self) -> bool:
        return bool(os.environ.get('OPENAI_API_KEY'))

def create_provider():
    return OpenAIProvider()
```

### 2.2 在 Bot 中使用

```yaml
# bot.yaml
ai_provider: openai_api
```

### 2.3 Provider 优先级（可细粒度控制）

```yaml
# 整个 Bot 默认用 openai_api
ai_provider: openai_api

# 特定 Phase 用 deepseek_api（在 registry.yaml 中）
phases:
  p7:
    ai_provider: deepseek_api   # 只有 p7 蒸馏 用 DS
```

```python
# 特定 Skill 指定 Provider（在 MANIFEST 中）
MANIFEST = SkillManifest(
    name="fast_reply",
    ai_provider: "deepseek_api",   # 此 Skill 永远走 DS
    ...
)
```

**优先级链**：`Skill 指定 > Phase 指定 > Bot 默认 > 全局兜底(claude_cli)`

### 2.4 Provider 降级机制

```python
# executor.py 中内置：指定 Provider 不可用时自动降级
def get_ai_provider(ctx):
    ...
    if not provider:
        fallback = runtime.config.ai_provider or 'claude_cli'
        provider = runtime.provider_registry.get_instance(fallback)
    return provider
```

## 三、新增 Tool（全局共享工具）

Tool 是**无状态的工具函数集合**，被任意 Skill 和 Hook 调用。

### 3.1 接口约定

```python
# tools/my_tool.py
from core.context import ToolManifest

# 可选（用于注册表发现和文档）
MANIFEST = ToolManifest(name="my_tool", description="工具描述")

def do_something(param: str) -> str:
    """纯函数，无状态，无副作用（或副作用明确）。"""
    return result
```

### 3.2 在 Skill 中使用

```python
# Skill 内部直接 import
from tools.feishu_token import get_token
from tools.file_write import write_file, git_commit
from tools.feishu_message import send_text
```

### 3.3 现有 Tools 速查

| 文件 | 函数 | 功能 |
|------|------|------|
| `feishu_token.py` | `get_token(app_id, secret)` | 获取飞书 access_token |
| `feishu_message.py` | `send_text(token, uid, text)` | 发送飞书文本消息 |
| `feishu_file.py` | `send_file_to_user(token, uid, path)` | 发飞书文件 |
| `file_write.py` | `write_file(path, content)`, `git_commit(path, ws, msg)` | 写文件+Git提交 |
| `file_read.py` | `read_file(path)`, `list_files(dir)` | 读文件 |
| `search_grep.py` | `grep(pattern, dir)` | 知识库搜索 |
| `wechat_fetch.py` | `fetch_article(url)` | 抓取微信文章 |

## 四、新增 Bot（完整流程）

### 4.1 最快方式：复制模板

```bash
cp -r bots/_template bots/health_v2
```

### 4.2 修改 bot.yaml

```yaml
# bots/health_v2/bot.yaml
name: health_v2
label: "健康管理Bot v2"
enabled: true
description: "健康数据追踪与分析"
channel: feishu_ws
channel_config:
  app_id: ${FEISHU_HEALTH_APP_ID}
  app_secret: ${FEISHU_HEALTH_APP_SECRET}
ai_provider: deepseek_api
workspace: "/home/zy/健康数据/"
max_concurrent: 3
default_timeout: 120
global_hooks: [dedup, auth, timer, audit]
```

### 4.3 添加环境变量到 start.sh

```bash
export FEISHU_HEALTH_APP_ID=cli_xxxx
export FEISHU_HEALTH_APP_SECRET=xxxxx
```

### 4.4 开发 Skills

```bash
# 在 bots/health_v2/skills/ 目录下新建 .py 文件
# 参考 docs/01_Skill开发与进化手册.md
```

### 4.5 Bot 隔离保证

| 资源 | 隔离级别 |
|------|---------|
| 飞书应用 | 完全独立（不同 APP_ID/SECRET）|
| 进程 | 完全独立（子进程启动）|
| skill_registry | 完全独立（各自加载） |
| pipeline / hooks | 完全独立（各自实例化）|
| pending_store | 命名空间隔离（以 bot_name 为前缀）|
| tool_registry | 共享（只读，无副作用）|
| provider_registry | 共享（只读，无副作用）|
| global_hooks | 共享代码，独立实例 |

> **结论**：删除或修改任何一个 Bot 的 Skills，完全不影响其他 Bot。

## 五、Phase 扩展

Phase 是"有 prompt 文件的 Skill 模板"，由 `phase_execute` 统一调度。

### 5.1 新增 Phase

**Step 1**：写 prompt 文件

```markdown
<!-- bots/investment/prompts/phases/phase12_my_analysis.md -->
你是一个专业的...
请处理以下内容：
```

**Step 2**：在 registry.yaml 中注册

```yaml
# bots/investment/prompts/registry.yaml
phases:
  p12:
    key: "p12"
    label: "Phase12 我的分析"
    prompt_file: "phases/phase12_my_analysis.md"
    triggers: ["我的分析", "分析X"]
    timeout: 300
    output_dir: "研究/分析结果"
    needs_confirm: true      # true=预览+确认; false=直接写入
    accepts_inline: true     # true=触发词后可以直接附内容
    ai_provider: ""          # 空=用Bot默认
```

**Step 3**：重启 Bot 生效（无需改代码）

### 5.2 卸载 Phase

```yaml
# 从 registry.yaml 中删除对应条目，或注释掉
# phases:
#   p12: ...      ← 注释掉
```

## 六、架构扩展检查清单

新增任何模块前，对照以下清单确认接口满足要求：

```
Skill  ✅ 有 MANIFEST（name/description/triggers/priority）
       ✅ 有 handle(ctx) → Context
       ✅ 不直接 import 其他 Skill
       ✅ 通过 get_ai_provider(ctx) 获取 Provider
       ✅ 通过 tools.* 调用工具

Hook   ✅ 有 MANIFEST（name/phase/priority）
       ✅ before hook 返回 ctx
       ✅ 不在 hook 中调用 AI

Channel ✅ 有 MANIFEST
        ✅ 实现 start(runtime) 和 send_reply(ctx)
        ✅ 有 create_channel() 工厂函数
        ✅ 通过 execute_in_runtime() 处理消息

Provider ✅ 有 MANIFEST
         ✅ 继承 ProviderBase
         ✅ 实现 call() 和 check_available()
         ✅ 有 create_provider() 工厂函数
         ✅ 错误时返回 "❌ ..." 或 "⏸️ ..."（不抛异常）

Tool   ✅ 纯函数或明确副作用
       ✅ 无状态（不保存实例变量）
       ✅ 错误时抛出异常或返回 None（由调用方处理）
```
