# 文档设计反思 — Agent 协作知识卡

> 版本：2026-04-13 | 从 investment_system 项目实战中提炼  
> 适用场景：任何需要 AI agent（Claude/GPT/DeepSeek）参与开发维护的代码项目

---

## 一、本项目暴露的三类文档问题

### 问题1：入口文档（CLAUDE.md）长期不同步 ⭐ 最高危

**现象**：`CLAUDE.md` 描述的目录结构是旧架构（`bot_claude/` `bot_gemini/`），实际代码已迁移到 `bots/investment/` `bots/investment_ds/`。

**后果**：agent 读入口文档后去错误目录找代码，定位问题需要额外的自行探索时间，且容易在错误目录做出修改。

**根本原因**：重构时只改了代码，没有同步更新文档。文档没有被当作"代码的一部分"来维护。

**解决原则**：
> 入口文档（README / CLAUDE.md）改动频率应与代码改动**绑定**。  
> 每次重构后的第一件事：更新入口文档，再提交代码。

---

### 问题2：非显而易见的设计决策未文档化 ⭐ 中等危

**现象**：`ingest_file` 的 `triggers=[]`（空触发词）是刻意设计，原因是由 Channel 层直接注入路由。但没有任何注释或文档说明"为什么是空的"。

**后果**：agent 看到触发词为空，不知道是 bug 还是设计，需要通读 `feishu_ws.py` + `router.py` 才能理解。遇到用户说 `ok` 无法路由回 skill 时，定位路径更长。

**解决原则**：
> 凡是"反直觉"的设计——例如空触发词、跳过某一层的逻辑、硬编码的特殊行为——  
> **必须在代码注释 + 架构文档中同时说明**，写清楚"为什么"而不只是"是什么"。

---

### 问题3：多文件同步关系未声明 ⭐ 容易引入不一致

**现象**：`bots/investment/skills/` 和 `bots/investment_ds/skills/` 是内容相同的 Copy（非 symlink），但没有任何地方说明"修一个必须改另一个"。

**后果**：本次修复 DeepSeek bot 后，靠 `diff` 命令才发现 Claude bot 也需要同步修改，差点漏掉。这类问题在多次迭代后会积累成两个 bot 行为不一致的隐患。

**解决原则**：
> 凡是存在**内容必须保持一致的文件副本**，必须在以下至少一处声明：
> 1. 入口文档（CLAUDE.md）的显著位置
> 2. 各目录自身的 README
> 3. 代码顶部注释 `# ⚠️ 此文件在 bots/investment/ 和 bots/investment_ds/ 中有副本，修改必须同步`

## 二、Agent 协作文档设计通用原则

### 原则1：分层文档，明确读者

| 文档层级 | 文件位置 | 读者 | 核心内容 |
|---------|---------|------|---------|
| **入口层** | `CLAUDE.md` / `README.md` | agent 首次读取 | 目录结构、运行方式、关键约束、路由速查 |
| **架构层** | `docs/00_架构总览.md` | 理解系统设计 | 数据流、分层职责、已知问题 |
| **模块层** | 各目录 `README.md` | 修改具体模块 | 该模块的职责、接口、注意事项 |
| **代码层** | 函数注释 | 修改具体函数 | 为什么这样实现、边缘案例 |

### 原则2：入口文档 = 导航地图，不是详细说明书

入口文档的价值在于**让 agent 在 30 秒内知道去哪里找代码**，而不是罗列所有细节。应包含：
- ✅ 目录结构（反映当前真实状态）
- ✅ 关键约束（git 操作规范、文件同步规则）
- ✅ 路由/流程速查（排查最常见 bug 的路径）
- ❌ 不应包含：详细的实现逻辑（放在代码注释或架构文档）

### 原则3：文档有效性的两个检验问题

做完任何一次重构后，问自己：

> **问题 A**：如果一个完全不了解这个项目的 agent 只读 CLAUDE.md，它能找到这个功能对应的文件吗？

> **问题 B**：如果这个 agent 发现了一个 bug，它知道修一个文件后还需要同步修改哪些文件吗？

两个问题都能回答"是"，文档才算合格。

## 三、本项目已采纳的文档修复措施

| 问题 | 修复措施 | 文件 |
|------|---------|------|
| 入口文档过期 | 完整重写，包含路由速查表和 Skill 流程说明 | `CLAUDE.md` |
| 路由机制无文档 | 架构总览新增"路由机制专项说明"章节 | `docs/00_架构总览.md` |
| Skills 同步规则无声明 | CLAUDE.md 显著位置声明，各 Bot 目录加 README | `CLAUDE.md` `bots/*/README.md` |
| ingest_file 空触发词无说明 | 代码注释已更新，CLAUDE.md 路由速查有说明 | `ingest_file.py` `CLAUDE.md` |

## 四、持续维护建议

```
每次修改代码前，问自己：
  "这个改动会让入口文档失效吗？"

每次修改完成后，检查：
  1. CLAUDE.md 的目录结构是否还准确？
  2. 有没有新增"内容副本"关系需要声明？
  3. 有没有新的"反直觉设计"需要说明？
```
