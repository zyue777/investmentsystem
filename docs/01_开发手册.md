> 本手册涵盖 Agent Hub 所有可扩展模块的开发规范。  
> 新增任何模块前先读对应章节，最后对照「扩展检查清单」验收。

## 一、Skill 开发

### 1.1 Skill 是什么

Skill 是 Agent Hub 的**最小业务单元**。每个 Skill 是一个独立 Python 文件，负责处理一种用户意图。

- **只接收** `Context` 对象，**只返回** `Context` 对象
- **不知道** 消息从哪来、发给谁
- **不关心** 用哪个 AI provider（由框架注入）
- 存放位置：`bots/_shared/skills/`（共享）或 `bots/<name>/skills/`（Bot 专属覆盖）

### 1.2 最小模板

```python
# bots/_shared/skills/my_skill.py
from core.context import Context, ContextStatus, SkillManifest

MANIFEST = SkillManifest(
    name="my_skill",           # 唯一标识符
    description="一句话描述，≤50字，供 AI 意图分类使用",
    triggers=["指令前缀 "],    # 触发词列表，注意末尾空格
    version="1.0.0",
    tags=["分类标签"],
    priority=50,               # 数字越小优先级越高
)

def handle(ctx: Context) -> Context:
    from core.executor import get_ai_provider
    provider = get_ai_provider(ctx)
    if not provider:
        ctx.reply_text = "❌ AI模型不可用"
        ctx.status = ContextStatus.ERROR
        return ctx
    result = provider.call_with_retry(f"处理：\n{ctx.raw_text}", timeout=60)
    ctx.reply_text = result
    ctx.status = ContextStatus.SUCCESS
    return ctx
```

### 1.3 触发词规范

```python
# ✅ 末尾加空格，防止误触
triggers=["录 ", "问 ", "析 "]
# ✅ 完整词，无歧义
triggers=["ping", "/stop"]
# ❌ 无空格会截断：triggers=["录"] → "录音" 也会被匹配
```

### 1.4 优先级设计

| 优先级 | 用途 | 示例 |
|--------|------|------|
| P10 | 系统指令（零Token）| `system_status` |
| P15 | 内容录入 | `ingest_record` |
| P20 | 自动触发 / 研究模式 | `ingest_url`, `memo_save`, `research_session` |
| P25 | 模式切换 | `dialog_mode` |
| P40 | Phase 执行器 | `phase_execute` |
| P50 | 通用 AI 问答 | `kb_query` |

### 1.5 Context 状态机

```
CREATED → ROUTED → EXECUTING → SUCCESS / ERROR / PENDING / CANCELLED
```

- `PENDING`：写入 `pending_store`，等用户回复 ok
- `CANCELLED`：静默丢弃，不发任何回复
- `ERROR`：用 `ctx.reply_text` 回复错误
- `SUCCESS`：用 `ctx.reply_text` 回复结果

### 1.6 Skill 生命周期

```
新增：放文件到 _shared/skills/ → 重启生效
修改：直接编辑 .py → 重启生效
禁用：MANIFEST 设 triggers=[], priority=999
卸载：删除文件 → 重启后自动消失（零副作用）
```

### 1.7 禁止项

```python
# ❌ 直接 import 其他 Skill
# ❌ 在 Skill 中发飞书消息（绕过 Channel）
# ❌ catch 所有异常并静默
# ❌ 在 Skill 中执行 git 命令
```

### 1.8 Shared Skill 开发铁律

`_shared/skills/` 文件被所有 Bot 共用，以下规则**优先级最高**：

```python
# ❌ 用相对路径访问 Bot 级文件（__file__ 指向 _shared/，不是 bot 目录）
prompt_file = Path(__file__).parent.parent / 'prompts' / 'classify.md'

# ✅ 通过 runtime 注入获取 Bot 实际目录
runtime = ctx.metadata.get('_runtime')
prompt_file = runtime.bot_dir / 'prompts' / 'classify.md'
```

```python
# ❌ 信任 AI 输出直接当文件路径
path = Path(ws) / ai_output_path
path.parent.mkdir(parents=True)  # AI 输出带反引号/非法前缀 → 创建垃圾目录

# ✅ AI 输出经过净化函数后再用
clean_path = _sanitize_path(ai_output_path, today, source_name)
path = Path(ws) / clean_path
```

> ⚠️ 教训来源（2026-04-13）：`ingest_file.py` 同时踩中以上两条，导致分类退化 + 创建垃圾文件夹 + 路径腐化。

## 二、Hook 开发

Hook 是**横切关注点**（去重/鉴权/计时/审计），在 Skill 前后自动执行。

### 2.1 执行时机

```
[before] dedup(P10) → auth(P20) → timer(P30) → Skill.handle(ctx) → [after] timer_after(P30) → audit(P20)
```

### 2.2 模板

```python
# hooks/my_hook.py
from core.context import Context, ContextStatus, HookManifest

MANIFEST = HookManifest(name="my_hook", phase="before", priority=50, enabled=True)

def handle(ctx: Context) -> Context:
    # before hook 必须返回 ctx
    # 中断后续：ctx.status = ContextStatus.CANCELLED
    return ctx
```

### 2.3 全局 vs Bot 专属

| 类型 | 目录 | 激活方式 |
|------|------|---------|
| 全局 | `hooks/` | `bot.yaml` 的 `global_hooks` 列表 |
| Bot 专属 | `bots/<name>/hooks/` | 自动加载 |

### 2.4 禁止项

```python
# ❌ before hook 不返回 ctx → 管道断裂
# ❌ after hook 修改 reply_text → 此时回复已发出
# ❌ Hook 中调用 AI → 每条消息额外延迟+Token
```

## 三、Channel / Provider / Tool 开发

### 3.1 Channel（渠道适配器）

```python
# channels/my_channel.py
class MyChannel(ChannelBase):
    def start(self, runtime): ...    # 启动监听（可阻塞）
    def send_reply(self, ctx): ...   # 发回复
def create_channel(): return MyChannel()
```

切换渠道：改 `bot.yaml` 一行 → 重启 → Skills/Hooks/Tools 完全不动。

### 3.2 Provider（AI 引擎）

**所有投研 Bot 统一走 `litellm`**，双 Bot 通过 env 前缀独立配置 API：

| Bot | bot.yaml 字段 | .env 前缀 |
|-----|--------------|-----------|
| investment（群1） | `ai_model/api_base/api_key: ${AI_*_INVEST}` | `AI_MODEL_INVEST` 等 |
| investment_ds（群2） | `ai_model/api_base/api_key: ${AI_*_DS}` | `AI_MODEL_DS` 等 |

**bot.yaml 模板**：
```yaml
ai_provider: litellm
ai_model: ${AI_MODEL_DS}
ai_api_base: ${AI_API_BASE_DS}
ai_api_key: ${AI_API_KEY_DS}
```

`executor.get_ai_provider()` 自动将 Bot 级配置绑定到 LiteLLM Provider，Skill 代码零改动。

**常用模型字符串**：
```
openai/claude-sonnet-4-6     ← Invest Bot 中转站
openai/deepseek-v4-pro       ← DS Bot 直连
gemini/gemini-2.5-flash      ← 需云端 xray 代理
openai/kimi-k2.5             ← 国内中转站
```

> `claude_cli` 已废弃（本地 relay），保留文件仅供回滚。LiteLLM 已支持 100+ 模型，无需新写 Provider。

```python
# providers/my_special_provider.py（仅特殊情况需要）
class MySpecialProvider(ProviderBase):
    def call(self, prompt, timeout=300, cwd="", **kwargs) -> str: ...
    def check_available(self) -> bool: ...
def create_provider(): return MySpecialProvider()
```

优先级链：`Skill 指定 > Phase 指定 > Bot 默认 > 全局兑底`

## 四、Phase 扩展

Phase 是"有 prompt 文件的 Skill 模板"，由 `phase_execute` 统一调度。

```yaml
# bots/<name>/prompts/registry.yaml
phases:
  p12:
    key: "p12"
    label: "Phase12 我的分析"
    prompt_file: "phases/phase12_my_analysis.md"
    triggers: ["我的分析"]
    needs_confirm: true      # true=预览+确认; false=直接写入
    ai_provider: ""          # 空=用Bot默认
```

新增 Phase = 写 prompt .md + 加 registry.yaml 条目 → 重启（零代码）。

## 五、新增 Bot（完整流程）

```bash
cp -r bots/_template bots/my_bot    # 复制模板
# 修改 bot.yaml：
#   name: my_bot
#   channel_config: app_id/secret
#   ai_provider: litellm
#   ai_model: ${AI_MODEL_XXX}
#   ai_api_base: ${AI_API_BASE_XXX}
#   ai_api_key: ${AI_API_KEY_XXX}
#   workspace: /path/to/kb
# .env 中确认对应前缀的 model/base/key 已设置
# 重启 → BotLoader 自动发现
```

Bot 隔离保证：进程独立 / registry 独立 / pipeline 独立 / pending_store 命名空间隔离 / AI 配置独立。

## 六、扩展检查清单

```
Skill（文字触发）：✅ MANIFEST + handle(ctx) + 不 import 其他 Skill
Skill（文件类）：  ✅ 上述 + triggers=[] + bot.yaml file_skill_routes 声明
Hook：            ✅ MANIFEST + before 返回 ctx + 不调 AI
Channel：         ✅ MANIFEST + start()+send_reply() + create_channel()
Provider：        ✅ MANIFEST + call()+check_available() + create_provider()
Tool：            ✅ 纯函数 + 无状态 + 异常由调用方处理
```
